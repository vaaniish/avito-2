# Восстановление Diploma

## Из Git

1. Скачать репозиторий, установить и запустить Docker.
2. Выполнить `./start-demo.sh` из каталога репозитория.
3. Открыть http://localhost:8080 и войти одним из аккаунтов в README.

В Windows можно использовать WSL/Git Bash либо напрямую:

```bash
docker compose --env-file infra/demo.env -f compose.demo.yml up --build -d --wait --wait-timeout 600
```

Для первого запуска из Git нужен интернет: скачиваются закреплённые образы
и npm-зависимости. После сборки приложение запускается без этих загрузок.
Первоначальное наполнение полного каталога требует не менее 6 ГБ RAM,
выделенных Docker. Seed использует порции данных и лимит Node.js 4 ГБ;
в обычном режиме импорта нет.

## Что сохранено

| Данные | Способ восстановления |
| --- | --- |
| Код, миграции, изображения интерфейса и демо-товаров | Git |
| Полный справочник каталога | `data/archive/catalog-reference.json.gz` |
| Контрольные суммы и количество записей каталога | `data/archive/catalog-reference.manifest.json` |
| Node.js, PostgreSQL, Nginx | Docker-образы закреплены по digest |
| npm-зависимости | `npm ci` по `package-lock.json` |
| Пользователи, объявления, заказы | Новый запуск `backend/prisma/seed.ts` |
| Личные API-ключи и старая база | Для этого сценария не требуются, в Git не включены |

Архив каталога содержит 254 ветки, 6 360 записей брендов в ветках,
89 099 моделей и 110 050 вариантов. Это снимок местного справочника
от 12 октября 2026 года; для его восстановления не нужен повторный сбор
данных с DNS. Генератор в `scripts/catalog/` остаётся вспомогательным инструментом.

Для распаковки каталога при локальной разработке: `npm run catalog:restore`.
Распакованный JSON находится в игнорируемом `data/catalog-reference/generated/`.

## Повторный запуск и данные

Docker создаёт отдельный volume `avito-diploma-demo_demo_postgres`.
Bootstrap применяет миграции; если в базе уже есть пользователи и отметка
успешного завершения seed, наполнение пропускается. Отметка хранится в комментарии
к демо-базе PostgreSQL. Повторный запуск и `down` сохраняют изменения.

Если первый seed был прерван, проверить журнал bootstrap. Для полностью нового
демо можно удалить **только его** volume следующей командой. Все изменения
в демо-базе будут потеряны:

```bash
docker compose --env-file infra/demo.env -f compose.demo.yml down --volumes
./start-demo.sh
```

Не применять эти команды к другим Compose-файлам или рабочим базам.

Логи и состояние:

```bash
docker compose --env-file infra/demo.env -f compose.demo.yml ps -a
docker compose --env-file infra/demo.env -f compose.demo.yml logs --tail=100 bootstrap backend
```

Если порт 8080 занят, изменить `DEMO_HTTP_PORT` в `infra/demo.env` и использовать
этот порт в браузере. Ключи внешних сервисов не требуются для запуска; интерактивные
карты и настоящие запросы к сервисам требуют актуальной конфигурации.

## Автономная копия для долгого хранения

Git фиксирует исходники и каталог, но не гарантирует вечную доступность Docker
Registry и npm. Можно сохранить уже собранные образы и исходники отдельно:

```bash
./start-demo.sh
./scripts/demo/export-offline.sh /path/to/Diploma-offline
```

Экспорт содержит `source.tar.gz`, `images.tar.gz`, контрольные суммы и скрипт
`start-offline.sh`. Личных ключей и базы там нет. Скопировать всю папку в надёжное
хранилище. Для восстановления достаточно Docker и запуска `./start-offline.sh`;
загрузка из registry/npm не потребуется. Образы привязаны к архитектуре машины,
на которой экспорт выполнен (например, ARM64 для Apple Silicon).

## Проверки

Сборка: `npm run ci:verify`. Проверка уже запущенного демо в браузере:

```bash
npm ci
npx playwright install chromium
npm run test:demo:ui
```

UI-проверки создают тестовые действия в демо-базе. Для unit/integration/API
использовать отдельную тестовую базу и `DOTENV_CONFIG_PATH=/dev/null`, чтобы
случайно не загрузить личные настройки внешних сервисов.
